## Color

The site has two simultaneous visual surfaces:

1. **MkDocs site (light + dark via Material palette toggle)** — body, cards, links, navigation. Palette is theme-default; do **not** introduce custom CSS for Phase 6.
2. **Plotly charts (single dark surface, mode-agnostic)** — embedded as PNG (Twitter hero) and `.html` (interactive). Charts render with `cfd_dark` template against both light and dark site themes. Accepted tradeoff: charts are visually distinct from page chrome in light mode (a dark "screen" within the page); this matches every existing chart on the site (CfD dynamics, RO dynamics, etc.) — Phase 6 X-charts inherit the convention without breaking it.

### Site-level color (Material defaults)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | Material `--md-default-bg-color` (light: `#ffffff`; dark: `#0e1116`) | Page background, body surface |
| Secondary (30%) | Material `--md-default-fg-color--lightest` for card backgrounds; `--md-primary-fg-color` for nav | Headline-card background, scheme-grid tile background, navigation strip |
| Accent (10%) | Material `--md-accent-fg-color` (theme default: `#5e35b1` indigo light / corresponding dark variant) | Inline link color; **headline-card numbers** (`£N.N bn` etc.) — render as default-text-color, not accent (numbers are not links); **`[Interactive version]` link below each X-chart PNG** (the only link styled as such on a chart-page); placeholder-tile labels are body-text-color, **not** accent (placeholder tiles are non-clickable per D-10) |
| Destructive | not applicable | Phase 6 introduces no destructive actions. No delete buttons, no irreversible UI. |

Accent reserved for: inline body-text links; `[Interactive version](path.html){target="_blank"}` links beneath every embedded chart; Material-theme-rendered focus rings on links/cards (theme default — do not override). **Not** used for: headline-card numbers; chart-internal axis text; placeholder-tile labels; chart subtitles; the under-cards caveat line.

### Per-scheme palette (NEW — introduced in Phase 6 for cross-scheme charts)

The X1, X4, X5 charts need stable, distinct, accessible colors per scheme. Phase 6 declares the palette covering all 8 schemes so Phases 7-12 each consume a one-line mapping (no palette renegotiation as schemes ship).

**Selection criteria** (locked):
1. **Colorblind-safe** — palette is built around the [Tol bright qualitative palette](https://personal.sron.nl/~pault/) (8 colors, deuteranopia/protanopia/tritanopia tested). Every adjacent pair distinguishable by the three most common forms of colorblindness.
2. **Reuse where possible** — CfD's existing offshore-wind blue `#1f77b4` (already in `colors.py::TECHNOLOGY_COLORS`) is the CfD scheme color, so the X-charts visually anchor to the cfd.md S3 chart's blue band. Biomass red `#d62728` is the "biggest legacy contributor" in the RO story (Drax) and is the RO scheme color.
3. **Stable across X-chart variants** — same scheme = same color in X1 (stack), X4 (per-MWh bar), X5 (2022 grouped bar). A reader who recognises "blue = CfD" on X1 carries that recognition across pages.
4. **Anti-aliasing-safe in PNG** — every chosen hex passes WCAG AA contrast against the Plotly `PLOT_BG` (`#252936`), confirmed at the 1200×675 export resolution.
5. **Provenance discipline** — the palette lives as a top-of-file constant `SCHEME_COLORS: dict[str, str]` in `src/uk_subsidy_tracker/plotting/colors.py` with a `Provenance:` docstring per the project convention (`constant_provenance_pattern.md` in user memory). The docstring cites Tol bright as basis and pins the colorblind-safe tradeoff.

| Scheme | Color | Hex | Why | Phase shipped |
|--------|-------|-----|-----|---------------|
| CfD | Blue (offshore-wind anchor) | `#1f77b4` | Already locked in `TECHNOLOGY_COLORS["Offshore Wind"]`; CfD's biggest band on `cfd.md` S3 | Phase 6 |
| RO | Red (biomass anchor) | `#d62728` | Already locked in `TECHNOLOGY_COLORS["Biomass"]`; RO's biggest band on `ro.md` S3 (Drax-dominated) | Phase 6 |
| FiT | Orange | `#ff7f0e` | Already locked in `TECHNOLOGY_COLORS["Solar PV"]`; FiT is dominated by domestic solar PV — the same hex stays consistent with theme charts | Phase 7 (reserved slot) |
| Constraint Payments | Teal | `#17becf` | Tol bright; visually distinct from the wind colors despite payments going to wind farms | Phase 8 (reserved slot) |
| Capacity Market | Purple | `#9467bd` | Already in `ALLOCATION_ROUND_COLORS["Allocation Round 4"]`; reuse minimises cross-codebase palette drift | Phase 9 (reserved slot) |
| Balancing Services | Olive | `#bcbd22` | Existing fallback in `colors.py::create_color_map`; distinct from teal at colorblind-safe distance | Phase 10 (reserved slot) |

**Stack order on X1** (vertical position in the stacked bar): bottom-up by total cumulative cost. Phase 6 today: RO at the bottom (£58.6 bn covered, larger), CfD on top (£29 bn). As Phases 7-12 land, the stack re-sorts every regenerate; locked sort is `cross_scheme.parquet.groupby('scheme')['cost_gbp'].sum().sort_values(ascending=True)` — biggest scheme at the bottom is the readability convention.

## Component Inventory (project-specific)

This phase ships three new visual constructs and modifies one existing one. Each is described below as a contract executor + auditor consume.

### 1. Headline-card row (NEW on `docs/index.md`, above the existing 2×4 scheme grid)

**Pattern:** Material `grid cards` extension, **3 cards in one row at desktop**, identical to `docs/themes/cost/index.md` lines 9-59 in markup style; collapses to 2 cards / 1 card at progressively narrower viewports per Material's responsive defaults (no breakpoint override).

**Contract per card:**
- **Markdown source** lives directly in `docs/index.md` immediately under `# UK Renewable Subsidy Tracker` and the introductory paragraph; **above** the existing `## Schemes` H2.
- **Card layout (locked):**
  - Line 1 (large): `**£N.N bn**` — number in bold; rendered at headline-card-number type token (28px / 700).
  - Line 2 (small): `Total subsidy (latest scheme year)` — label at headline-card-label type token (14px / 400).
  - **No body, no link, no icon, no horizontal rule between.** This is a stat card, not a navigation card. Cards are non-clickable.
- **Three card payloads** (exact label copy locked below in Copywriting Contract):
  1. Card A: `**£N.N bn**` / `Total subsidy (latest scheme year)`
  2. Card B: `**£N.N bn**` / `Premium over gas (latest scheme year)`
  3. Card C: `**£NN**` / `Per household (latest scheme year)`
- **Caveat line beneath the card row:** rendered as `*Covers 2 of 8 schemes; full coverage in Phases 7-12.*` (single italic line, body-text-color, 14px). Sits one paragraph-break below the cards, one paragraph-break above the X1 hero PNG.
- **Numbers are hardcoded markdown** (D-09); `tests/test_headline_sync.py` regression-tests them against `cross_scheme.parquet`.
- **Number-formatting convention** — literal `£` prefix; `bn` suffix for billions to 1 decimal place (e.g. `£87.5 bn`); **no space** between digit and `bn` matches existing scheme-page convention (cfd.md uses `£14bn` and `£14.0bn` interchangeably; Phase 6 locks the **with-space** form `£87.5 bn` for headline cards because the larger 28px size visually merits the breath; **without-space** `£87bn` form remains acceptable inline in body text). For per-household, format as `£NN` (no decimal), e.g. `£3,200`.

### 2. X1 hero embed (NEW on `docs/index.md`, between the headline-card row and the existing 2×4 scheme grid)

**Pattern:** identical to every existing scheme/theme chart embed:
```markdown
![Total UK subsidy stacked by scheme — covered schemes only](charts/html/x1_stacked_total_twitter.png)

[Interactive version](charts/html/x1_stacked_total.html){target="_blank"}
```

**Twitter PNG** dimensions: 1200×675 @ scale=2 (locked by `ChartBuilder.save(export_twitter=True)`). PNG shows **All-time view** (no rangeselector buttons; PNG is a static hero).

**Interactive HTML** carries Plotly native `rangeselector` buttons. Locked specifications:
- Buttons (left-to-right): `1y` / `5y` / `All`
- **Default-active button on page load:** `All` (consistent with the PNG hero; readers see the same scope by default whether they click through or not)
- **Position:** above the plotting area, top-left (`x=0.0, y=1.02, xanchor="left", yanchor="bottom"`)
- **Activation logic:** Plotly built-in — clicking a button updates the x-axis range only; bar values, stack order, legend, subtitle remain static
- **Implementation:** `fig.update_xaxes(rangeselector=dict(buttons=[dict(count=1, label="1y", step="year", stepmode="backward"), dict(count=5, label="5y", step="year", stepmode="backward"), dict(label="All", step="all")]))` — verbatim Plotly API, no custom JS

**Chart subtitle (X1 only, both PNG + HTML):** `Covers 2 of 8 schemes — see scheme grid for coverage status.` Rendered at chart-subtitle type token (12px / `#a0a4b8`), left-aligned beneath the chart title.

### 6. `mkdocs.yml` Portal nav placement (LOCKED)

**Decision:** `Portal` is a **top-level** nav tab (not a sub-section under `Schemes` or `Themes`). Rationale:
- Cross-scheme symmetry principle (Phase 05.1 D-02): readers learn the X-chart reading pattern once. Burying Portal under Schemes would frame X-charts as scheme-adjacent rather than the cross-scheme tier they are.
- ARCH §5.4 catalogues X-charts in a dedicated cross-scheme bucket — a top-level tab honours that IA decision.
- Material `navigation.tabs` is already enabled (`mkdocs.yml` line 23) — adding a tab is a one-block edit.
- Position in tab order: between `Schemes` and `Data` (so the read flow is: per-scheme detail → cross-scheme aggregation → download the data).

**Locked nav block (drop-in for `mkdocs.yml`):**
