## Decisions Made

1. **Dropped `active=2` from X1's rangeselector.** Plotly 6.x's `go.layout.XAxis.RangeSelector` has no `active` property — only `activecolor` (button color when clicked). The plan/UI-SPEC specified `active=2` to default to "All" but this is not a real Plotly property; setting it raises `ValueError`. The default rendered state (no button highlighted, axis at full range) IS the "All" view, so the visual contract is preserved.
2. **Chart artefacts gitignored.** Consistent with the existing 18 chart artefacts — the regen pipeline produces them on demand; they don't need to be in git.
3. **X3 subtitle on a single line.** Originally split across two adjacent string literals (Python concatenates at compile time, so the rendered output is correct), but the plan's verbatim-grep acceptance criterion only matches if the source line itself contains the full subtitle. Collapsed to one line for grep-discoverability.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] X1 rangeselector `active=2` is invalid in Plotly 6.x**

- **Found during:** Task 1 first smoke-test run.
- **Issue:** Plan specified `rangeselector=dict(buttons=[...], active=2)` to default to the "All" button being highlighted. Plotly 6.x raised `ValueError: Bad property path: active ^^^^^^ Did you mean "activecolor"?` — `RangeSelector` has only `activecolor` (the button-highlight color), not `active`. The PNG export succeeded (PNG path doesn't touch `update_xaxes`), but the HTML export aborted before writing the file.
- **Fix:** Removed `active=2`. The default state (no button highlighted, axis displaying full range) IS the "All" view, so the visual contract from UI-SPEC §"X1 hero embed" is preserved. Added an explanatory inline comment.
- **Files modified:** `src/uk_subsidy_tracker/plotting/portal/x1_stacked_total.py`
- **Verification:** Re-ran `uv run python -m uk_subsidy_tracker.plotting.portal.x1_stacked_total`; all three artefacts (PNG, HTML, div.html) emitted. `grep -c rangeselector docs/charts/html/x1_stacked_total.html` returns 2 (buttons present in HTML).
- **Committed in:** `af88e07` (Task 1 commit; the fix shipped before Task 1 was committed).

**2. [Rule 1 - Bug] X3 subtitle split across literals fails verbatim-grep acceptance**

- **Found during:** Task 2 acceptance verification.
- **Issue:** I initially wrote the X3 subtitle as `"Covers 2 of 8 schemes; ONS UK households-count "` + `"denominator — see methodology."` (two adjacent string literals on consecutive lines). Python's compile-time concatenation produces the correct rendered output (verified with `grep` on the HTML file), but the source-file grep `grep -c "Covers 2 of 8 schemes; ONS UK households-count denominator" x3_per_household.py` returned 0 because grep matches per-line.
- **Fix:** Consolidated the subtitle to a single source line. Rendered output unchanged.
- **Files modified:** `src/uk_subsidy_tracker/plotting/portal/x3_per_household.py`
- **Verification:** Source grep returns 1; HTML grep still returns 1; `uv run python -m uk_subsidy_tracker.plotting.portal.x3_per_household` succeeds.
- **Committed in:** `bfc335b` (Task 2 commit; both Task 2 files committed together with the fix in place).
